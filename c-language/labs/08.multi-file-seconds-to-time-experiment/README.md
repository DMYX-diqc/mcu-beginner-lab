# 08. 多文件工程：秒值转时间值

> 目录：`08.multi-file-seconds-to-time-experiment`

## 实验目的

通过本实验，掌握 C 语言**多文件工程**的组织方式，理解模块化开发：

1. 掌握 `.c`（实现）与 `.h`（接口声明）的分离；
2. 掌握头文件包含守卫 `#ifndef ... #define ... #endif` 的作用；
3. 理解「按功能拆分模块」的思想，学会多个源文件协同编译。

## 实验内容

把「秒值转时间值」拆分为多个模块：

- `CalcHour`：计算小时；
- `CalcMin`：计算分钟；
- `CalcSec`：计算秒；
- `App`：主程序，调用各模块。

每个模块都包含一个 `.h`（声明接口）和一个 `.c`（实现）。

## 涉及知识点

| 知识点 | 说明 |
| --- | --- |
| 多文件工程 | 多个 `.c` 协同编译 |
| 头文件 | `.h` 接口声明、`#include` |
| 包含守卫 | `#ifndef / #define / #endif` |
| 模块化 | 按功能拆分代码 |

## 运行环境

- 操作系统：Windows
- 开发工具：Visual Studio（或任意支持 C 的 IDE / 编译器）

## 编译与运行

1. 用 Visual Studio 打开 `Project` 目录下的工程文件（`.sln`）；
2. 在 `Code/` 下各模块的源文件与头文件中补全实现；
3. 编译运行后，按提示输入一个 0~86399 之间的整数；
4. 观察换算结果。

## 预期结果

输入 `3661`，输出：

```
Current time: 01-01-01
```

## 思考与拓展

1. 头文件为什么需要包含守卫？去掉会有什么风险？
2. 如果把某个模块的 `.c` 从工程里移除，编译时会报什么错？
